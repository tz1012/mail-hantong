# 내장 AI 메일 도구 자동 연결과 삭제 기능 변경안

상태: 사용자 승인된 계약 변경(2026-11-03). 로컬 구현과 자동 검사 반영. 실제 AI 서비스 시험·새 버전 배포·보안 코드 사람 검토는 별도로 남아 있다.

승인된 계약의 구체 기준은 [내장 AI 메일 접근과 검토된 휴지통 계약](../contracts/builtin-ai-mail.md)이다. 기존 계약 문서에는 이 승인된 확장을 반영했지만, 현재 공개 beta.3과 설치 바이너리는 변경하지 않았다.

## 사용자 요구와 적용 범위

2026-11-03 사용자는 내장 AI에 메일 접근·본문 읽기·작성·발송·삭제 도구가 자동 제공되어야 한다고 정정했다. 수동 `hantong-mcp register` → 요청 ID 복사 → `hantong review` → 상태 조회 → `/agent on` 절차를 내장 AI의 일반 이용 조건으로 요구하지 않는다. 외부 MCP 호스트 연결은 별도 기능이다.

도구 자동 제공는 전체 메일을 대화 시작마다 일괄 업로드한다는 뜻이 아니다. 모델은 실제 연결·허용된 계정의 도구 목록을 받고, 사용자의 요청에 따라 필요한 검색 결과·본문을 도구로 조회한다. 계정별 외부 AI 전송 정책을 매 호출 재검사한다. 메일 내용은 지시나 권한 증거가 아니다.

## 목표 사용자 흐름

1. 프로그램 설치·실행 → Google 계정 연결 → 이용할 메일 기능 선택.
2. AI 제공자 연결 후 AI 대화 시작. 최초 AI 기능 설정은 같은 터미널에서 제공자·대상 계정·외부로 전달될 데이터 범위를 설명한다. 별도의 등록 명령이나 요청 ID 복사를 요구하지 않는다. 기존의 계정별 외부 전송 기본 꺼짐 정책은 이 기능 설정으로 명시적으로 바꾸며, Google OAuth 동의를 외부 AI 전송 동의로 간주하지 않는다.
3. 설정이 끝난 계정의 지원 도구는 AI 대화마다 자동 연결한다. `/agent on`은 필수 단계가 아니며 `/agent off`는 해당 세션의 도구 연결을 끊는다. 제공자 변경 시 기존 대화는 이관하지 않고 새 제공자의 전송 정책을 확인한다.
4. 읽기·검색·본문 조회·로컬 초안 작성은 허용 범위에서 바로 이용한다. 발송·삭제는 AI가 불변 요청을 만들고 사용자가 같은 터미널에서 내용을 확인한다. AI 응답이나 메일 본문의 확인 문구는 실행 근거가 아니다.
5. 권한이 부족하면 해당 기능의 설정·Google 추가 동의를 같은 이용 흐름에서 안내한다. 도구를 제공했다고 이미 실행 가능한 권한이 있다고 표시하지 않는다. 취소 시 원래 범위를 유지한다.

## 내장 AI와 외부 MCP 권한 분리

현재 `Agent::connect`는 공개 `hantong-mcp` 실행 파일과 고정 MCP 등록을 사용한다. 이 등록을 자동 확장하면 외부 MCP 호스트도 동일 권한을 얻으므로 이 방식은 채택하지 않는다.

내장 AI에는 별도 `ClientKind::Ai` 및 제공자별 보호 프로필 `ai-codex.json`, `ai-claude.json`을 도입하는 안을 제안한다. Core가 검증한 전용 실행 경로·키·등록·프로필 epoch에 결속한다. CLI 기본 키를 AI에 재사용하거나 호출자 `ai=true`, 프로세스 이름, TTY만으로 AI 권한을 만들지 않는다. 내장 연결은 전용 프로필만 쓰며 외부 `hantong-mcp` 기본 실행은 기존 MCP 프로필만 쓴다. 이 구분 역시 같은 Windows 사용자에 의한 자동화를 사람과 구별하는 증거는 아니다.

AI 설정은 Core 소유 터미널 도우미가 조정하며, 범용 승인 플래그/도구를 노출하지 않는다. 계정·제공자·도구·전송 범위·epoch를 한 번의 명시적 기능 설정에 결속한다. 빈 계정 목록은 전체 계정을 뜻하지 않는다. 새 계정 추가, 범위 확대, 철회·만료·제공자 변경을 기존 동의로 덮지 않는다. 기존 CLI/MCP 등록·동의·보안 이력은 그대로 보존하고 자동 확대하지 않는다.

## 삭제 의미와 실행 계약

기본 삭제는 단일 메일의 **휴지통 이동**으로 한다. 영구 삭제·휴지통 비우기·대량 삭제는 이번 변경에 포함하지 않는다. 사용자가 영구 삭제를 요청하면 지원하지 않는 동작이라고 안내한다.

Gmail 우선 구현은 `gmail.modify`를 실제로 받은 계정에서만 가능하다. 현재 읽기 또는 읽기·발송 계정은 별도 Google 권한 추가 없이 삭제할 수 없다. IMAP/다른 공급자는 공급자 capability와 해당 구현을 갖추기 전까지 삭제 지원으로 표시하지 않는다.

새로운 typed 휴지통 요청/상태 계약을 만들며 기존 라벨 변경의 TRASH 금지 조건을 풀어 우회하지 않는다. 요청은 계정·메시지 식별자·캐시 버전·operation_id·idempotency_key·내용 digest·등록/epoch·만료에 결속한다. Core가 전체 대상 preview를 생성하며 확인/취소는 같은 터미널에서 한다. 도구는 요청과 상태 조회만 제공하고 승인/직접 실행은 제공하지 않는다.

확인 전에는 공급자 호출을 하지 않는다. 실행 직전 현재 계정·권한·버전을 재검사하고 durable claim을 한 번만 소비한다. 응답 유실은 불확실 상태로 남기고 자동 재삭제하지 않는다. 성공 시 해당 캐시만 무효화한다. 감사 기록에는 메일 원문·제목·주소·비밀값을 넣지 않는다.

## 변경이 필요한 계약과 코드

- `docs/contracts/ai-managed-clients.md`: 내장 AI 자동 연결·전용 identity를 정의하고 외부 MCP의 명시 등록은 유지.
- `docs/contracts/google-personal-cli.md`, `client-registration.md`, `client-profile.md`, `registration-store.md`, `database.md`, `db-schema.sql`: AI 기능 설정·계정별 전송 동의·전용 등록/프로필·이전 데이터 보존 migration 정의.
- `docs/contracts/google-write.md`, `google-mutations.md`, 신규 도구 schema: 기존 영구·대량 삭제 제외를 유지한 채 별도의 단일 Gmail 휴지통 request/status 계약 추가. 공급자 capability·도구 공개·terminal review·감사/불확실 상태 정의.
- `crates/hantong-ai/src/{lib,agent}.rs`, `apps/hantong-cli/src/ai.rs`: 자동 연결, 제공자 변경/철회, 실패 상태·도구 발견, 세션별 off.
- contracts/IPC/Store/Core 등록·정책: AI identity와 계정별 동의 검증. 기존 MCP 키를 통한 새 권한 사용 차단.
- Secrets Google transport/Core mutation ledger: 정확한 휴지통 endpoint와 단일 시도 실행. 기존 send ledger는 그대로 유지.
- 홈페이지·README·CLI 도움말: 실제 구현/검증 후 일반 내장 AI 안내에서 수동 등록 절차 제거. 외부 MCP 고급 안내와 베타 제약은 구분.

## 수용 검사

- 등록 명령·요청 ID 복사·`/agent on` 없이 최초 설정부터 실제 도구 발견/호출까지 fake Core/provider 통합 검사.
- 내장 AI 권한으로 외부 MCP 프로필의 계정·도구·전송 범위가 늘지 않음.
- 계정 A/B 격리, 계정별 전송 비활성·철회·epoch 변경·제공자 변경·빈 계정·새 계정 추가의 차단.
- 읽기·본문·초안·발송 요청·휴지통 요청 도구의 실제 dispatch 및 지원 범위에 따른 발견 검사. parser/stub만으로 완료 판정 금지.
- 터미널 취소/EOF/비대화형 입력에는 권한 확장·발송·삭제가 없음. 확인 전 공급자 호출 0회, 확인 후 최대 1회.
- 휴지통 권한 부족·만료·내용/버전 변조·다른 계정·중복 요청·응답 유실·재시작에서도 직접/자동 재삭제가 없음.
- 기존 DB migration/rollback/FK/highwater·과거 등록 해시 보존, 비밀값/본문 로그 금지, 기존 전체 검사 회귀 없음.
- 실제 계정 OAuth·실제 발송·실제 삭제는 자동 시험에서 하지 않는다. 실제 삭제 시험은 별도 명시 권한이 있어야 한다.

## 현재 상태와 적용 경계

공개 beta.3은 여전히 AI 기본 off·독립 MCP 등록 방식이며 삭제를 지원하지 않는다. 승인된 계약만으로 사이트의 현재 기능을 자동 연결/삭제 지원이라고 바꾸거나 기존 베타 바이너리를 교체하지 않는다. 구현·통합 검증·사람 보안 검토가 끝나기 전에는 지원 기능으로 광고하지 않는다. 사용자 요구의 채택은 보안 코드의 사람 검토 완료를 뜻하지 않는다.
