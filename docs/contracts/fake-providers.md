# 가짜 공급자 시험 계약 v1

상태: 연속 개발 위임에 따른 구현 기준. M0-06 시험 도구 전용. 실제 공급자 호환성이나 제품 인증/발송 완료를 뜻하지 않는다.

`tests/Fakes`의 `hantong-test-support`는 제품 package의 일반·빌드 의존성으로 사용할 수 없다. 시험의 dev-dependency로만 연결한다. 네트워크·실제 계정·환경 자격증명을 사용하지 않는다.

- 모든 호출은 비어 있지 않은 `account_id`에 결속한다. 다른 계정 호출은 거부하며 호출 결과도 계정별로 분리한다.
- FakeGmail: 일반 성공, 만료된 history(404), rate limit(429), 제출 접수 후 응답 유실을 선택한다.
- FakeGraph: 페이지/nextLink를 순서대로 반환, delta 만료(410), 이동 후 ID 변경, sendMail 접수(202)를 선택한다.
- FakeSmtp: 성공, 인증 실패, 접수 후 응답 유실을 선택한다. 응답 유실은 서버 접수 횟수가 증가하지만 성공으로 보고하지 않는다.
- FakeOAuth: 일치하는 state로 한 번만 콜백을 처리, state 불일치·중복 콜백·부분 범위·갱신 실패·철회를 재현한다. fixture 문자열은 실제 토큰이 아니다.
- 시나리오와 호출 기록은 인스턴스에 속한다. 자동 재시도는 하지 않는다. 기록에 계정·작업·접수 여부를 남겨 중복 발송을 시험할 수 있게 한다.
- 잘못된 입력과 시나리오 소진은 명시적 오류로 반환하며 다음 계정이나 기본 성공으로 넘기지 않는다. 로그·오류에 fixture 비밀 문자열을 포함하지 않는다.

향후 실제 adapter 계약은 별도 문서와 계약 시험에서 이 가짜 동작과 연결한다. 이 골격의 통과를 Gmail·Graph·SMTP 인증/메일 기능의 수용 기준 통과로 올리지 않는다.
