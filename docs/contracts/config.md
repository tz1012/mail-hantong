# 설정 파일 계약 v1

상태: M1-05 구현 기준 초안, 사람 검토 필요. 기준 요건은 `INST-07`, `CLI-16`, `OPS-07`, `OPS-08`이다. 이 문서는 구조·변경 경계만 정의하며 저장소 구현이나 설정 명령의 완료를 의미하지 않는다.

## 파일과 버전

GUI와 `hantong` CLI는 같은 암호화 로컬 저장소의 설정 레코드를 사용한다. 외부에서 직접 경로를 지정하거나 별도 CLI 설정 파일을 만들지 않는다. `config.schema.json`의 `schema_version`은 형식 버전이고 `settings_version`은 낙관적 동시성 버전이다. 변경 요청은 읽은 `settings_version`을 함께 보내며, 저장은 내부 `settings` 행의 `version = expected_version` CAS로만 수행한다. JSON의 `settings_version`과 행의 `version`은 일치해야 한다. 영향 행이 0이면 `CONFLICT`이고 기존 설정을 그대로 유지한다. 버전은 성공한 변경마다 1씩 증가하며 0 또는 감소를 허용하지 않는다.

손으로 수정한 입력도 동일한 스키마와 런타임 검증을 통과해야 한다. 파싱, 스키마, enum, IANA 시간대, 정책 검증 중 하나라도 실패하면 새 값을 적용하거나 일부 필드만 병합하지 않고 이전 유효 값을 유지한다. 원자 교체와 파일 잠금은 저장소 계약을 따른다.

## 표시 언어와 테마

- CLI 언어는 `en` 또는 `ko`이며 기본값은 `en`이다. `--lang` 명시값, 저장된 `cli.language`, `en` 순서로 선택한다. JSON/NDJSON 키, 오류 코드, 도구 ID, 명령과 옵션 이름은 번역하지 않는다.
- GUI 언어는 선택값이 없으면 운영체제 언어가 한국어일 때 `ko`, 그 밖에는 `en`으로 초기화한다. 명시적으로 저장한 `gui.language`는 OS 언어 변경에도 유지한다. 언어 전환은 화면 문자열만 갱신하고 초안·첨부·선택·계정·승인 요청·메일 데이터·저장 시각을 변경하지 않는다.
- GUI 테마는 `light`, `dark`, `system`이다. 기본은 `system`이며, 명시 테마는 OS 테마 변경을 따르지 않는다. `system`은 실행 중 OS 변경을 반영한다. 대비 테마에서는 시스템 색을 우선한다. 본문 HTML 색을 강제로 반전하거나 외부 이미지 정책을 바꾸지 않는다.
- `locale.timezone_id`는 IANA 시간대 식별자다. JSON Schema의 `iana-timezone` 형식과 실제 tzdata 검증을 모두 통과해야 하며 서버·CLI·GUI가 임의로 바꾸지 않는다.

## 보호된 정책 설정

`security.external_ai_enabled`는 기본 `false`다. 이 값은 일반 `hantong config set`이나 에이전트·MCP 요청으로 변경할 수 없다. 변경이 필요하면 사람 확인이 결속된 보호 UI/승인 도우미 경로에서 정책과 범위를 검증한 뒤 전용 저장소 작업으로 적용한다. 전역 값을 켜도 계정별 `AI-07` 정책·승인·제공자 허용 범위를 대체하지 못하며 계정 접근 권한을 추가하지 않는다. 설정 파일에 직접 값을 넣어도 보호 경계를 우회하지 못한다. 토큰·앱 비밀번호·API 키는 이 스키마에 저장하지 않는다.

## M1-04와의 경계

M1-04의 `settings` 테이블은 `setting_key`, JSON 값, 행별 `version`, UTC 시각을 가진 내부 CAS 저장 원시 기능이다. 이 계약을 통과한 전역 설정만 그 행에 저장하며, 임의 SQL·임의 키·클라이언트의 SQLite 연결 공개는 없다. 설정 항목 추가·정책 범위 확대는 별도 계약과 보안 검토가 필요하다.
