# ADR-019 등록 키와 연결 세션

상태: 연속 개발 위임에 따른 설계 기준. **사람 보안 검토 필요**. 초기 제품 경로는 미등록 거부 상태를 유지한다.

표시 이름·PID·TTY·환경 변수·요청 client_id는 인증 증거가 아니다. CurrentUser DPAPI shared secret만 사용하는 방식도 같은 사용자의 다른 프로세스가 복호화할 수 있으므로 채택하지 않는다.

등록된 클라이언트는 Windows CNG의 non-exportable P-256 키로 연결마다 발급되는 일회성 challenge를 서명한다. 서버의 공개 키도 승인 도우미의 등록 절차에서 고정하고 서버를 상호 인증한다. 비밀 키 바이트를 export하거나 CLI/MCP에 반환하지 않는다. 클라이언트 이름은 등록 선택자다.

인증 세션은 서버 내부 연결 객체에만 존재한다. 재사용 가능한 bearer token을 반환하지 않으며 프로필 epoch·등록 철회·계정 해제 시 재검사한다. 등록 키 사용은 일반 도구 접근을 위한 인증이며 발송 승인은 별도의 사람 존재 확인·요청 결속·일회 소비가 필요하다.

키 보관 이름이나 Windows 사용자 ACL만으로 같은 사용자 악성코드를 모두 막을 수 없다. 키 사용 권한 탈취·프로세스 주입·관리자/커널 침해는 잔여 위험이다. 더 강한 격리가 필요하면 AppContainer/package identity·별도 broker 또는 세션별 Windows Hello를 추가 검토한다. 이 한계는 제품에 명시한다.

필수 검증: 동일 사용자 이름/TTY 위장, 다른 사용자 접속, 원격 pipe 접속, 서버 이름 선점, 다른 연결의 challenge 재사용, 응답 재생·만료·서명 변조, 등록/프로필 철회, 계정 범위 확대, 미등록 정보 노출. 실제 CNG 서명과 OS transport를 함께 시험하기 전에는 mock 인증 통과를 제품 검증으로 기록하지 않는다.

플랫폼 FFI는 전용 좁은 모듈에 두고 반환하는 것은 SID·공개 키·서명·불투명 키/연결 핸들뿐이다. DPAPI 평문은 Secrets 밖으로 반환하지 않는다. 플랫폼 전송 인터페이스 M0-10을 M1-02 전에 구현한다.
