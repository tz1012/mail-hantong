# ADR-016 프로젝트 라이선스

상태: **과거 비교 제안 보관 — [정식 ADR-016](../ADR-016-license.md)과 [LICENSE](../../../LICENSE)로 대체됨**

2026-10-29 사용자가 라이선스 문안을 정식 채택했다. 아래의 ‘검토 중’·‘채택 후’ 표현은 당시 제안 이력이며 현재 구현·배포 안내에는 위 정식 문안을 적용한다.

작성일·원문 확인일: 2026-10-29

관련 작업: M0-01 저장소 골격, GitHub 공개, M9-15 의존성·라이선스 고지

## 결정할 내용

사용자는 2026-10-29 “상업적 이용은 금지 수정본 비공개 허용”이라고 답한 뒤, 범위 확인 질문에서 2번인 **회사 내부 업무용 사용 허용, 프로그램 재판매·유료 서비스 제공 등 수익화 금지**를 선택했다. 프로젝트 소스는 GitHub에 공개하고 수정본의 소스 공개 의무는 두지 않는다. 제품 자체의 판매·유료 제공 제한과 일반적인 회사 업무에 사용하는 것을 구분한다.

## 확정된 사용 정책

개인 사용·회사 내부 업무용 사용은 허용하고, 이 프로그램이나 수정본의 재판매·유료 서비스 제공 등 프로그램 자체를 통한 수익화는 금지한다. 수정본의 소스 공개를 강제하지 않는다. MIT·Apache-2.0·GPLv3는 이 수익화 제한을 그대로 충족하지 않으므로 기존 MIT 추천은 철회한다.

재판매 제한이 있으므로 OSI 정의의 오픈소스로 표시하지 않고 **수익화 제한이 있는 소스 공개(source-available)**로 안내한다. 회사 내부 업무용 사용까지 금지한다는 오해를 줄이기 위해 ‘상업적 이용 전면 금지’라고만 표기하지 않는다. [OSI 정의 §1](https://opensource.org/osd)

| 사용 사례 | 사용자 선택에 따른 정책 |
| --- | --- |
| 개인이 자기 메일을 관리 | 허용 |
| 회사 직원이 내부 업무 메일을 관리 | 허용 |
| 수정한 코드를 공개하지 않고 허용된 용도로 사용 | 허용 |
| 원본 또는 수정본을 무료로 재배포 | 허용 — 수정 소스 공개 의무 없음 |
| 원본 또는 수정본을 판매하거나 유료 서비스로 제공 | 금지 |

사용자는 이어 “무료 재배포 허용”이라고 명시했다. 원본·수정본을 무료로 재배포할 수 있으며, 앞서 확정한 수정본 소스 공개 의무를 두지 않는 조건을 유지한다. 무료 실행 파일 배포에도 이 조건을 적용한다.

허용 범위는 사용자 선택으로 정해졌다. 실제 라이선스에는 회사 내부 업무용 사용 허용과 원본·수정본의 유료 제공 제한을 명확히 반영해야 한다. 정책을 포괄적인 비상업 표준 문구에 끼워 맞추어 내부 업무용 사용까지 차단하지 않는다. [라이선스 검토 초안](../../latest/LICENSING-DRAFT.md)에 영문 문안과 한국어 요약을 작성했다. 실제 라이선스 문구는 검토 중이다.

## 저작권자와 연락처

사용자가 2026-10-29 직접 제공한 표기를 사용한다.

```text
Copyright (c) 2026 Andrew Cho
Website: https://tzt.kr
Contact: andrew@tzt.kr
```

저작권자는 Andrew Cho이며 웹사이트와 이메일은 연락 정보다. 로컬 PC 사용자 이름을 저작권자로 추정하지 않는다.

이는 프로젝트 코드와 문서의 사용 정책이다. 선택한 언어·런타임의 라이선스가 프로젝트의 라이선스를 자동으로 정하지 않는다. 제3자 라이브러리·복사한 코드·이미지 등은 각 원저작물의 라이선스와 고지 조건을 별도로 확인한다. 프로젝트의 수익화 제한으로 제3자가 부여한 권리나 의무를 임의로 변경하지 않는다.

## 채택 후 할 일

1. 확정한 Andrew Cho 표기와 연락처를 사용한다. 무료 재배포 허용과 수정본 소스 공개 의무 없음이 문안에 함께 반영되었는지 확인한다.
2. 확정한 범위를 만족하는 라이선스 문구를 검토한 뒤 루트 LICENSE와 README에 반영한다. 현재 정책 확인만으로 LICENSE를 추가하거나 공개 권한을 부여한 것으로 표시하지 않는다.
3. 의존성 선정·설치 패키지 제작 시 호환성과 필요한 고지·SBOM을 확인한다.

## 재검토 조건

사용자의 재배포 정책이 달라지거나 채택할 의존성과의 호환성 문제가 발견되면 공개 전에 다시 검토한다. 이미 공개한 버전의 권리가 선택 변경으로 자동 소멸한다고 가정하지 않는다.
