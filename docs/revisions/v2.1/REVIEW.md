# 채택 전 검토할 결정

상태: 전 항목 검토 대기. 검토자·승인 시각·근거는 아직 없다. 표의 제안은 개정 문서에 반영한 문안이며 승인된 구현을 뜻하지 않는다.

| 항목 | 개정안의 제안 | 영향과 확인할 사항 |
| --- | --- | --- |
| R1 클라이언트 인증 | 이름·TTY를 인증에서 제외하고 주체·세션·등록을 결속. 미등록 accounts.list 금지 | 등록 전 계정 선택 UX가 달라진다. ADR-019에서 동일 사용자 프로세스의 위장·증거 탈취·철회 공격과 실현 가능한 격리 범위를 검증해야 한다. |
| R2 일반 승인 보호 | 일반 GUI도 사용자 확인 증거를 요구. 고위험은 추가 검토 | 일반 발송의 조작 횟수가 늘 수 있다. 구체 수단은 ADR-015에서 선택하며 Hello 호출 성공만으로 내용 결속을 입증했다고 보지 않는다. |
| R3 코어 설치와 TOTP | 보안 설정은 승인 도우미, TOTP는 P1 보호 입력 경로 | 코어 설치에도 작은 네이티브 화면이 필요하다. Hello를 사용할 수 없는 환경의 발송을 무조건 지원한다고 약속하지 않으며 대체 수단은 검증 후 연다. |
| R4 서버 업로드 지원 | 원문·날짜·서버 규칙·외부 알림 조건을 검증한 조합만 지원 | Gmail insert/import, Graph FTS와 계정·권한 제약, IMAP APPEND를 구분해야 한다. 미확인 경로의 비활성화로 P0를 충족했다고 처리하지 않는다. 출시 지원 범위를 좁힐 경우 별도 요건 승인이 필요하다. |
| R5 계획 갱신과 게이트 | 진행을 막는 오류는 PLAN으로 즉시 제안. P0와 P1 선행 분리 | 승인 기록 없이 카드 범위를 자동 변경하지 않는다. 스누즈 P0·IDLE/Gmail 복구·데스크톱 승인 알림은 Gate 1에 유지한다. |
| R6 완료의 증거 | AC별 적용 범위·시험·결과·검토자 기록 | M0-00에서 복합 수용기준을 분할하고 대응표를 검토한다. 이번 색인은 요건↔카드 대응일 뿐 수용시험 구현·통과 증거가 아니다. |

채택 후에도 ADR-001~019의 개별 기술 결정, 계약 작성·승인, 실제 구현·시험은 별도 작업이다. 특정 SDK·인증 방식·제공자 기능을 이번 문서 수정만으로 확정하지 않는다.
