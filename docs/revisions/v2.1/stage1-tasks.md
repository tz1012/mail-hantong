# 1단계 작업 카드

상태: 사람 검토 필요 / 채택 전 개정안

대상: 로드맵 1단계(본인 전용 Windows PC) · 기준: 요건서 v2.1 개정안(v2.0 기반), 개발 지침서 v2.1
규칙: AGENTS.md §3 절차를 따른다. 선행 카드가 끝나지 않은 카드는 시작하지 않는다.
검토: `에이전트` = 테스트 통과 시 완료 가능, `사람` = 사람 검토 후 완료(AGENTS.md §6).

카드별 상태의 기준은 `card-status.csv`다. 마일스톤 체크박스는 요약이며 개별 카드의 완료·검토 증거를 대체하지 않는다. 현재 모든 카드는 미착수이고 승인된 ADR·계약은 이 패키지에 없다.

**진행 규칙**
- 각 마일스톤은 `M<n>-99 다음 마일스톤 계획 갱신` 카드로 끝난다. 긴급 범위·선행 오류는 `PLAN-YYYYMMDD-NN` 변경제안으로 먼저 수정하고 사람이 승인하면 반영한다.
- 진행 중 카드 내용이 실제 코드와 맞지 않으면 임의로 바꾸지 말고, 보고서의 "남은 일·알려진 제약"에 수정 제안을 적는다. 일반 제안은 99 카드에서, 진행을 막는 오류는 위 PLAN 변경제안으로 처리한다.
- 시작 가능한 카드가 없으면 새 작업을 만들지 않는다. 막힌 카드, 필요한 결정(ADR·계약·검토), 그 결정을 내릴 사람이 볼 자료를 보고하고 멈춘다.
- 1단계 P0 카드가 모두 끝나고 게이트(M9-12)를 통과하면 M10(1단계 P1)과 M9-99(2단계 준비)를 진행한다.

---

공통 선행: 표의 카드 선행 외에 사용 기술 ADR, 계약, 보안 검토 승인이 필요하다. 카드에 계약 산출물과 구현이 함께 있으면 계약 제안·승인 후 구현 순서이며, 카드의 검토 열보다 AGENTS §6의 검토 범위가 우선한다. 인증·승인이 준비되지 않은 초기 구현은 가짜 제공자 테스트로 제한하고 보호된 제품 호출은 거부한다.

개발·CI는 가짜 제공자를 사용한다. 프로토콜·권한·업로드 가정은 해당 마일스톤에서 사람이 확인할 검증 절차와 증거 형식을 먼저 마련한다. 사람이 실행한 임시 검증은 M9-05에 이관하며 비밀·메일 원문을 보고서에 넣지 않는다. 결과가 없으면 실제 호환성은 미검증으로 남고 Gate 1에서 통과 처리하지 않는다.

범위 표기: `M0-99~M8-99`는 M0부터 M8까지 각 99 카드만 뜻한다. `M5-01~06`은 같은 마일스톤의 연속 번호를 뜻한다. `M<n> 나머지 전부`는 자기 자신을 제외한다. 문서의 표보다 상태장부의 최신 증거가 완료 판정의 근거다.
