## 이번 개정에서 해결한 사항

- 클라이언트 이름·환경 변수·대화형 터미널을 인증 증거로 취급하지 않는다. 등록 전 계정 목록 예외도 제거한다.
- 일반 GUI 승인에도 사용자 확인 증거를 요구하고, 키 입력만으로 승인하지 않는다. 코어 설치의 보안 설정은 승인 도우미에서 처리한다.
- 서버 업로드는 계정·형식·권한·날짜·서버 부작용까지 검증한 조합만 허용한다. 미지원 거부를 P0 충족으로 세지 않는다.
- 현재 계획이 막혔을 때 99 카드 완료를 기다리지 않고 변경안을 검토할 수 있다. 카드 상태 갱신과 범위 변경을 구분한다.
- 스누즈 P0와 예약 발송 P1을 구분하고, 선택 P1 카드가 Gate 1을 막지 않도록 선행을 정리했다.
- 요건 ID 태그가 아닌 개별 수용기준·단계·시험 증거로 완료를 판정한다.

## 채택과 남은 작업

루트 `AGENTS.md` §6·§7은 보안·계약·요건 변경의 사람 검토를 요구한다. 따라서 이번 결과는 승인 사실을 대신 기록하지 않은 개정 패키지다. [검토 목록](REVIEW.md)의 결정을 확인한 뒤 세 문서와 요건서를 같은 기준으로 채택한다. 이후 M0-00에서 채택한 Word 요건서를 영역별 Markdown으로 분할하고, 개별 수용기준 ID를 확정한다.

현재 `docs/contracts/`, 확정 ADR, 제품 코드, 빌드·테스트 스크립트는 없다. 이 패키지의 계약 경로·명령·기술 표는 향후 만들 대상이다. 이번 문서 검증은 제품 빌드·보안 시험·실계정 호환성 검증을 대신하지 않는다.

기술적으로 남은 핵심 결정은 동일 사용자 프로세스 사이의 클라이언트 인증(ADR-019), 승인 채널의 사용자 확인·요청 결속(ADR-015), 서버 업로드의 실제 지원 조합이다. 이 결정에 필요한 기준과 선행 조건을 문서에 적었으며 특정 구현이나 공급자 지원을 확정하지 않았다.
