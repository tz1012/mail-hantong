# Rust / .NET Native AOT 초기 성능 비교

측정일: 2026-10-29. 상태: **소규모 비교 실험 완료. 후속 사용자 결정으로 코어·CLI에 Rust 채택**. 측정 수치와 실험 한계는 보존한다.

현재 Windows 시제품에서는 .NET Native AOT의 프로세스 시작이 빨랐고 Rust의 메모리 사용량과 실행 파일이 작았다. 검색은 작업별로 결과가 달랐다. 동일 실행 파일로 두 차례 측정했으며 이 방향은 반복되었다. 이 결과는 두 시제품의 비교이고, 언어의 보편적 우열이나 제품의 1초 시작 목표 달성을 뜻하지 않는다.

## 환경과 방법

- Windows 11 Pro x64, 빌드 26200. AMD Ryzen 5 7500F, 6코어/12스레드, 설치 RAM 약 32GB. D:는 CT2000P5PSSD8 NVMe SSD로 확인했다. 문서의 4코어·16GB 기준 장비와 다르다.
- 전원 설정은 기존 균형 조정을 유지했다. 백신 제외·프로세스 우선순위 변경·OS 캐시 강제 제거는 하지 않았다. 백그라운드 부하를 완전히 통제한 전용 시험 장비는 아니다.
- Rust/rustc/cargo 1.92.0, MSVC x64, Release `opt-level=3`, 외부 crate 없음. 기존 설치 도구를 사용했으며 최신 Rust 릴리스와의 비교는 아니다.
- .NET SDK 10.0.403, 런타임 팩 10.0.14, win-x64 Native AOT Release, 속도 최적화. Microsoft 배포 파일의 SHA-512를 확인해 `.tools/`에만 설치했다. 네이티브 컴파일 응답 파일의 `--Ot`도 확인했다.
- 양쪽 모두 ID·계정·UTC·읽음 상태·제목·발신자·요약을 보관한다. Rust는 구조체 벡터, C#은 readonly record struct 목록이다. 표준 라이브러리의 파싱·검색과 문자열 표현(UTF-8/UTF-16), 메모리 회수 방식은 다르다.
- 합성 메타데이터 100,000건, 계정 5개, 한글·영문 혼합, 정렬되지 않은 입력, 본문 128 KiB. 실제 메일·계정·토큰은 사용하지 않는다.
- 각 실행은 후보별 준비 실행 3회와 측정 40라운드다. 라운드마다 후보 순서를 교대하고 새 프로세스를 만든다. 같은 조건으로 2회 실행했다. 데이터·실행 파일·소스 해시와 빌드 설정이 두 실행에서 같음을 확인했다.
- 상주 작업은 라운드별로 계정 5개의 요청을 수행해 지표당 200개 응답을 기록한다. 이들은 **40개 프로세스에 묶인 반복 측정**이며 독립 프로세스 200개의 표본이 아니다.
- 모든 출력은 독립 Python 기준 결과와 비교했다. 평균 대신 중앙값과 nearest-rank P95를 아래에 제시한다. 원시 표본과 준비 실행 결과도 보관했다.

## 결과

각 셀은 **중앙값 / P95**, 시간 단위는 ms이며 작을수록 빠르다. 0.1ms 이하 목록 차이에는 측정기·파이프·스케줄링 비용의 영향이 크다.

| --- | ---: | ---: | ---: | ---: |
| 새 프로세스 → PONG 응답·종료 | 193.376 / 217.901 | 63.719 / 72.808 | 190.680 / 222.670 | 63.333 / 76.477 |
| 새 프로세스 → 10만 건 읽기·정렬·READY | 296.156 / 314.286 | 267.842 / 292.350 | 291.515 / 330.667 | 262.912 / 337.335 |
| 상주 목록 100개 | 0.082 / 0.126 | 0.089 / 0.239 | 0.081 / 0.120 | 0.088 / 0.250 |
| 상주 영문 제목 검색 `invoice` | 3.537 / 3.968 | 3.375 / 3.674 | 3.600 / 3.949 | 3.464 / 3.822 |
| 상주 한글 제목 검색 `회의` | 2.740 / 3.061 | 3.247 / 3.608 | 2.827 / 3.138 | 3.319 / 3.689 |
| 상주 요약 검색 `quarterly` | 4.709 / 5.399 | 3.283 / 3.709 | 4.805 / 5.529 | 3.399 / 3.882 |
| 상주 미일치 검색 | 2.772 / 3.173 | 2.848 / 3.457 | 2.874 / 3.245 | 3.024 / 3.525 |
| 상주 본문 파일 읽기·바이트 합계 | 0.363 / 0.445 | 0.359 / 0.412 | 0.355 / 0.452 | 0.354 / 0.412 |

프로세스 시작은 파일 캐시가 준비된 Windows에서 실행 요청부터 측정한 값이다. 디스크 콜드 시작이나 순수 런타임 초기화만의 비용은 아니다. 로드 READY 중앙값은 .NET이 낮지만, 2회차 P95는 .NET 337.335ms로 Rust 330.667ms보다 높았다. 모든 시작 지표에서 일관되게 우세하다고 해석하지 않는다.

메모리 값은 MiB 단위이며 각 실행의 중앙값이다. Working set은 해당 시점의 실제 상주 페이지, private bytes는 프로세스 전용 커밋 메모리이며 같은 개념이 아니다.

| 자원 | 1회차 Rust | 1회차 .NET AOT | 2회차 Rust | 2회차 .NET AOT |
| --- | ---: | ---: | ---: | ---: |
| READY working set | 30.93 | 100.54 | 30.93 | 100.64 |
| READY private bytes | 26.67 | 95.13 | 26.67 | 95.21 |
| 작업 후 peak working set | 45.58 | 103.58 | 45.57 | 103.68 |
| 상주 요청 30개 CPU 시간(ms) | 70.31 | 62.50 | 62.50 | 62.50 |

Rust 실행 파일은 **181,760 bytes**, .NET AOT는 **1,558,528 bytes**다. PDB를 제외한 이 실험의 EXE 크기이며, 제품 설치 크기나 필요한 OS 구성 요소 전체 크기는 아니다. .NET의 현재 문자열 파싱·임시 할당·GC 영향이 메모리에 포함된다. 이 차이를 최적화된 제품에서도 유지되는 고정 비용으로 단정하지 않는다. CPU 시간은 Windows `GetProcessTimes`의 해상도 때문에 짧은 작업 비교에는 제한이 있다.

동일 라운드에서 Rust 중앙값 − .NET 중앙값을 구하면, 두 실행에서 PONG 시작 차이는 각각 **+130.705 / +126.919ms**, 캐시 로드 차이는 **+26.519 / +24.576ms**, 한글 검색 차이는 **−0.504 / −0.530ms**, 요약 검색 차이는 **+1.321 / +1.427ms**였다. 이는 라운드별 짝 비교 요약이며 통계적 유의성이나 다른 장비에서의 재현을 보증하는 수치는 아니다.

## 해석과 다음 결정

실험 직후에는 빠른 프로세스 실행을 근거로 .NET 10 Native AOT 후속 검증을 우선 제안했다. 이후 사용자가 “시작이 좀 느리지만 메모리 관리도 중요하니 Rust로 가자”라고 결정해 **코어·CLI에 Rust를 채택**했다. 이 선택은 시작 속도와 메모리 사용의 절충이며, .NET이 더 빨랐던 측정값을 바꾸지 않는다. 낮은 메모리 사용과 일부 검색 경로에서는 Rust가 유리했고, 실제 라이브러리와 저장소를 연결하면 성능 차이는 달라질 수 있다.

제품 1초 목표는 GUI 목록이 표시되고 입력에 반응해야 한다. 이번 READY에는 GUI·실제 DB·검색 인덱스·MIME·공급자 SDK·인증 IPC·정책/승인 검사가 없다. 이 경로의 결과로 해당 검사를 생략할 수 없다. 실제 라이브러리의 AOT 호환성, 한국어·영어 리소스 및 문화권 처리, 장시간 상주·동시 작업·메모리 증가와 Mac 실행도 검증 전이다. .NET의 `InvariantGlobalization=true`는 이 순서 비교 실험 설정일 뿐 제품 국제화 정책으로 채택하지 않는다.

[ADR-001](../adr/ADR-001-core-runtime.md)에 Rust 채택과 후속 검증 조건을 기록했다. 1초 시작 목표는 유지한다. 이후 [ADR-016](../adr/ADR-016-license.md)의 라이선스와 [M0-00 기준 요건](../requirements/README.md)도 사용자 승인으로 채택했다. 제품 계약·구현·실제 성능 검증은 별도다.

## 검증과 재현 자료

- 실험 검사 **10개** 통과: 양 언어에 같은 7개 동작 검사와 측정기·데이터·통계 검사 3개. 계정 분리·상위 100개 제한·한글·대소문자·빈 결과·잘못된 입력·원문 오류 노출 방지를 확인했다.
- Rust Release 빌드·format·Clippy와 .NET Native AOT 게시·format 검사를 통과했다. 제품 전체 `check-all`은 제품 골격이 없어 실행 대상이 아니다.
- 기존 문서 도구 검사 21개와 원문 분할본의 `--check`도 통과했다. 관련 로컬 링크 61개와 원본 Word 보존을 확인했고, 두 결과 파일의 모든 중앙값·P95·표본 수·소스/바이너리 해시를 재검산했다.
