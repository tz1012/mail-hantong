# 작업 전 남은 검토 항목

기준: v2.3, 2026년 10월 29일. 아래는 이전 개정에서 이어진 기술·계약 검토 항목이며 해당 항목들의 승인 증거는 별도로 관리한다. 제품 이름, CLI 이름, 기본 메일 기능의 P0 범위, GUI 영·한·테마 및 CLI 영어 지원은 이미 사용자 요청으로 정해졌으며 다시 결정할 항목이 아니다. 코어·CLI의 **Rust 채택도 [ADR-001](../adr/ADR-001-core-runtime.md)에서 사용자 승인으로 확정**했다. GUI·개별 라이브러리·계약을 함께 승인한 것은 아니다.

| 항목 | 현재 문서의 방향 | 확정할 내용과 관련 작업 |
| --- | --- | --- |
| R1 클라이언트 인증 | 이름·TTY를 인증으로 쓰지 않고 호출 주체·세션·등록을 결속한다. 미등록 계정 목록 조회는 차단한다. | ADR-019에서 동일 사용자 프로세스의 위장·증거 탈취·철회 공격과 실현 가능한 격리 범위를 검증한다. |
| R2 일반 승인 보호 | 일반 GUI도 사용자 확인 증거를 요구하고 고위험 동작은 추가 검토한다. | ADR-015에서 확인 수단과 요청·내용 결속을 검증한다. Hello 호출 성공만으로 결속을 입증한 것으로 보지 않는다. |
| R3 코어 설치와 TOTP | 보안 설정은 승인 도우미에서 처리한다. TOTP는 P1의 보호된 입력 경로다. | Hello를 사용할 수 없는 환경의 대체 수단을 검증하고 지원 범위를 결정한다. 도우미도 최초 화면부터 영·한·세 테마를 적용한다. |
| R4 서버 업로드 | 원문·날짜 보존과 서버 규칙·외부 알림의 영향을 검증한 조합만 지원한다. | 제공자·계정·권한별 capability와 날짜·부작용 조건을 확인한다. 미지원 경로를 비활성화한 사실만으로 P0 충족을 선언하지 않는다. |
| R5 계획 갱신과 게이트 | 진행을 막는 계획 오류는 PLAN 변경안으로 제안한다. P0와 선택 P1의 선행 관계를 분리한다. | 카드 범위 변경과 검토 기록을 관리한다. 현재 Gate 1에는 예약·자동화·기본 메일 기능·CLI 영어·GUI 언어·테마가 포함된다. |
| R6 완료의 증거 | 수용기준별 적용 범위·시험·결과·검토자를 기록한다. | M0-00에서 복합 수용기준을 분할하고 대응표를 검토한다. 현재 색인은 요건↔카드 연결이며 구현 시험 증거가 아니다. |

ADR-001~019의 개별 기술 결정, 계약 작성·승인과 실제 구현·시험은 [개발 지침](DEVELOPMENT_GUIDE.md)과 [작업 카드](stage1-tasks.md)에 따라 진행한다. GUI 프레임워크·정확한 색상값·치수 등 디자인 세부 결정은 [DESIGN.md](DESIGN.md)의 남은 디자인 결정에 정리돼 있다.

추가 확정: [ADR-016](../adr/ADR-016-license.md)의 프로젝트 라이선스 Version 1.0과 [M0-00 기준 요건](../requirements/README.md)도 사용자가 채택했다. M0-01은 [상태장부](card-status.csv)의 M0-00 검증 완료 근거를 확인하고 시작한다. 문서 채택과 제3자 라이선스·계약·보안 구현 검토는 별개다.
