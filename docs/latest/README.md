## 이미 정한 제품 범위

- 제품·솔루션 이름: **mail-hantong**. CLI 명령: **hantong**.
- 코어 데몬·CLI 구현 언어: **Rust 1.95.0**. 시작 속도와 메모리를 함께 고려한 [ADR-001 결정](../adr/ADR-001-core-runtime.md)을 따른다. 실제 빌드 명령은 [루트 README](../../README.md), 현재 구현 경계는 [Rust 구조](RUST-STRUCTURE.md)에 정리한다.
- 예약메일함·폴더·태그·기본 자동화·즐겨찾기·스팸함·광고필터·임시보관함·주소록은 모두 1단계 필수다.
- GUI는 첫 구현부터 한국어·영어와 라이트·다크·시스템 테마를 지원한다.
- CLI는 첫 구현부터 영어를 기본 지원하고 한국어 선택을 제공한다.
- 메일 발송은 사람 승인과 내용 결속을 거친다.

v2.3의 요건은 **170개**, 1단계 P0는 **144개**, 작업 카드는 **151개**다. 현재 작업과 검증 결과는 [진행 기록](PROGRESS.md), 카드별 상태는 [상태장부](card-status.csv)에서 확인한다. GitHub 공개 목표를 추가한 것만으로 1단계 제품 지원 범위나 미정 기술이 바뀌지는 않는다.

사용자가 승인한 후속 변경은 Markdown에 반영한다. 현재 앱 시작 목표는 **웜 캐시 상태에서 메일 목록 사용까지 1초 이내**이며, [기능 범위의 성능 보완](FEATURES.md)이 Word 원문 §13.1의 3초 목표를 대체한다. Word와 원문 추출본은 원본 기록으로 보관한다.

## 작업 지시 예시

공개 사용 정책은 **개인·회사 내부 업무용 사용, 수정본 비공개 및 원본·수정본 무료 재배포 허용, 프로그램 재판매·유료 서비스 제공 등 수익화 금지**다. 저작권자는 **Andrew Cho**, 웹사이트는 **https://tzt.kr**, 연락처는 **andrew@tzt.kr**이다. 사용자가 [정식 라이선스 Version 1.0](../../LICENSE)을 채택했고 [한국어 안내](LICENSING.md)와 [ADR-016](../adr/ADR-016-license.md)에 반영했다. GitHub 게시와 릴리스는 아직 수행하지 않았다.

Mac 후속 지원도 사용자 승인으로 목표에 포함됐다. Windows 우선 출시는 유지하며, Mac은 코어·CLI·최소 승인 도우미를 먼저 제공하고 전체 GUI를 후속 제공한다. 구체적인 범위는 [FEATURES.md](FEATURES.md)의 Mac 지원 보완을 따른다. 현재 배포 가능한 Mac 제품은 없다.

카드를 지정할 때는 아래 문장을 사용할 수 있다.

> `docs/latest/README.md`와 `docs/latest/stage1-tasks.md`를 기준으로 [카드 ID] 작업을 진행해줘. 선행 조건과 관련 요건·계약을 먼저 확인하고, 변경 내용과 검증 결과를 보고해줘.

처음 시작할 작업을 정할 때는 다음처럼 지시할 수 있다.

> `docs/latest/PROGRESS.md`와 `card-status.csv`를 읽고 현재 구현에서 이어서 진행해줘. 관련 기준 요건·계약·ADR을 확인하고, 검증 결과와 미완료 기능을 같은 진행 기록에 반영해줘.

GUI 작업을 지시할 때는 `DESIGN.md`와 OPS-07·08을, CLI 작업을 지시할 때는 CLI-01·02·07·16을 함께 지정한다. 기능 이름만 쓰는 것보다 카드 ID를 함께 쓰면 범위와 완료 조건을 명확히 할 수 있다.

이 모음은 최신 작업 지시용 진입점이다. 기준 요건은 사용자 승인으로 `docs/requirements/`에 채택했고 Rust·라이선스 ADR도 확정했다. 사용자의 연속 개발 위임에 따라 일반 구현 결정과 계약을 작성하며 진행한다. 이 위임을 사람 보안 검토 완료로 기록하지 않는다. `AGENTS.proposed.md`는 과거 개정안이며 현재 실행 규칙은 루트 `AGENTS.md`다. 현재 계획 정의와 상태장부는 계속 이 폴더에 있고 계약은 `docs/contracts/`에 작성되어 있다. `docs/plan/`은 후속 구조다. 카드 정의 상단의 채택 전 안내와 과거 문서는 작성 당시 상태이며 실제 승인·완료 여부는 현재 상태장부와 정식 ADR을 따른다.

원본과 과거 개정본은 기존 위치에 보존했다. 진행·상태는 작업마다 갱신하고, 정식 요건 개정 시에는 이 폴더의 관련 문서를 같은 개정에 맞추며 이전 상태를 보관한다. 날짜별 진행 보고서 사본은 만들지 않는다.
