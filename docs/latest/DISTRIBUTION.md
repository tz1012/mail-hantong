# mail-hantong GitHub 공개와 명령어 설치 계획

기록일: 2026-10-29. 사용자 확정 목표: **GitHub에 공개하여 다른 사람도 명령어로 설치하고 개발 작업을 시작할 수 있게 한다.** 제품 이름은 `mail-hantong`, 실행 명령은 `hantong`이다.

이 문서는 v2.3의 설치·출시 요건을 구체화하는 보완 자료다. 라이선스는 ADR-016의 Version 1.0으로 확정했다. 2026-10-30 사용자 지시로 GUI보다 CLI 출시를 우선한다. 공개 저장소는 [tz1012/mail-hantong](https://github.com/tz1012/mail-hantong)이며 Windows x64 개발 미리보기용 ZIP·체크섬과 PowerShell 한 줄 설치·업데이트를 제공한다. 정식 MSI/WinGet·서명·자동 업데이트 완료를 뜻하지 않는다. 실제 명령과 지원 범위는 [CLI 안내](CLI-LAUNCH.md)를 따른다.

## 공개 범위와 개발 단계

| 구분 | 목표 | 현재 개발 계획과의 관계 |
| --- | --- | --- |

| 명령어로 개발 시작 | 저장소 복제 후 안내된 준비 명령과 전체 검사 명령으로 개발 환경을 재현한다. | M0-01·02의 저장소·빌드·CI에 연결할 구체화 제안이다. 현재 카드의 범위·선행 조건을 자동 변경하지 않는다. |

| 불특정 다수의 계정 연결과 공개 운영 | 공개 앱의 OAuth·게시자·출시 운영 조건을 갖춘다. | 기존 3단계 공개 배포 범위를 유지한다. 소스 공개만으로 이 단계가 완료되지 않는다. |

GitHub 공개는 Linux 제품 지원, 휴대폰 앱, 공용 릴레이를 1단계에 추가한다는 뜻이 아니다. 공개 전 미완성 범위와 지원 환경을 README에 표시한다.

**Mac 후속 지원:** 사용자 승인(2026-10-29)에 따라 Windows 우선 출시 후 Mac 로컬 코어·CLI·최소 승인 도우미를 먼저 제공하고 전체 GUI를 후속 제공한다. Mac CLI도 OS별 코어와 보호된 계정 설정·승인 경로가 함께 준비돼야 한다. 상세 범위는 [Mac 후속 지원 방향](FEATURES.md)을 따른다. 출시 시점·단계·패키지 방식은 후속 계획에서 확정하고, 설치 명령은 실제 패키지 검증 후 제공한다.

## 일반 사용자의 설치 경로

완료된 설치 안내는 처음 사용하는 사람이 아래 흐름을 따라갈 수 있어야 한다.

1. 영문·한국어 안내에서 지원 Windows 버전·아키텍처와 전체 설치 또는 코어 설치를 확인한다. 코어 구성에도 사람 승인을 위한 승인 도우미를 포함한다.
2. 게시된 설치 명령을 실행한다. 최종 패키지 식별자와 배포 주소는 검증 후 실제 값으로 제공한다. 제품 실행에 Git, 개발 SDK, Docker 또는 WSL을 요구하지 않는다.
3. 새 터미널에서 `hantong --version`과 영어 기본 `hantong --help`로 설치·PATH 등록을 확인한다. 한국어 선택도 제공한다.
4. 설정 마법사에서 필요한 로그인·권한 확인을 사람이 수행한다. 명령어 설치의 성공과 메일 계정 연결 성공은 별도로 표시한다. 비밀번호나 토큰을 명령줄·저장소·설치 로그에 넣지 않는다.
5. 안내된 업데이트·제거 명령을 실행한다. 업데이트 실패 시 기존 버전을 유지하고, 제거 시 사용자 데이터의 보존·삭제 선택을 명확히 한다.

배포 수단 후보는 기존 ADR-011의 MSI와 WinGet이다. WinGet 설치를 제공하려면 실제 공개 설치 자산과 식별자, 설치 파일의 SHA-256, 설치·제거 정보가 있는 매니페스트와 제출 검증이 필요하다. 패키지 등록과 시험 전에는 실행 가능한 `winget install` 명령을 제공한 것으로 표시하지 않는다. [Microsoft 매니페스트 사양](https://learn.microsoft.com/en-us/windows/package-manager/package/manifest), [WinGet 제출 검증](https://learn.microsoft.com/en-us/windows/package-manager/package/winget-validation)

설치·갱신·제거와 전체/코어 구성은 깨끗한 Windows에서 확인한다. 실제 메일 연결은 사용자가 설정한 계정으로 수행하는 검증 모드에 남기며, 개발·CI 시험은 가짜 제공자를 사용한다.

## 기여자의 개발 경로

공개 저장소의 README에는 복사해서 실행할 수 있는 실제 명령을 다음 순서로 제공한다.

| 단계 | 제공할 내용 | 완료 기준 |
| --- | --- | --- |
| 소스 받기 | 확정된 저장소의 `git clone` 명령과 작업 폴더 진입 | 공개 읽기만으로 소스를 받을 수 있다. 기여자의 GitHub 인증은 PR을 올릴 때 별도로 안내한다. |
| 환경 준비 | 지원 셸과 정확한 SDK 버전, 하나의 준비 스크립트 명령 | 필요한 도구를 검사하고 빠진 항목·복구 방법을 알려 준다. 사용자별 절대 경로에 의존하지 않고 반복 실행할 수 있다. 도구 설치가 필요하면 변경 내용을 안내한다. |
| 전체 검사 | 빌드·단위/계약/통합·보안 시험·서식·요건 추적을 실행하는 명령 | 실패 시 0이 아닌 종료 코드와 원인을 반환한다. 실제 메일 계정·OAuth 등록·시크릿 없이 실행한다. 개발 전용 컨테이너가 필요한 검사는 준비 조건을 명시한다. |
| 로컬 실행 | 가짜 제공자를 사용하는 실행 예시와 샘플 설정 | 비밀값 없이 시험 가능한 흐름과 아직 비활성화된 제품 경로를 구분한다. |
| 작업 기여 | 카드 선택, 테스트 작성, 변경·검증 보고, PR 절차 | 요건 ID와 검증 증거를 연결하고 보안·계약 변경의 사람 검토 규칙을 따른다. |

Windows와 Linux CI의 검사 범위를 구분한다. Linux에서 플랫폼 독립 검사가 통과해도 Windows GUI·비밀 저장소·설치·승인 도우미 검증을 대신하지 않는다. SDK와 의존성 버전은 결정 후 저장소에 고정한다.

코어·CLI는 [ADR-001](../adr/ADR-001-core-runtime.md)에 따라 Rust로 확정했다. 제품 Rust toolchain·target·Cargo 빌드 명령과 준비 스크립트는 남은 선행 조건을 마치고 M0-01에서 실제로 구현한 뒤 README에 추가한다. 현재 문서 도구용 Python과 .NET 비교 시제품의 SDK는 제품 실행 요구 사항이 아니다.

[한국어 안내](LICENSING.md)와 [ADR-016](../adr/ADR-016-license.md)에 문안과 결정 근거를 기록했다. 업무용 사용까지 금지한다는 오해를 피하도록 허용 범위를 함께 표시하며, 정식 OSI 오픈소스로 표시하지 않는다. [OSI 정의 §1](https://opensource.org/osd)

개인 사용자의 OAuth 클라이언트 설정과 배포자가 운영하는 공개 OAuth 앱은 구분한다. 공개 앱은 실제 요청 범위·사용자 유형에 따른 검증 조건을 확인해야 한다. 이 준비를 설치 스크립트의 무인 로그인으로 대체하지 않는다. [Google OAuth 정책](https://developers.google.com/identity/protocols/oauth2/policies), [Google 민감 범위 검증](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification), [Microsoft 게시자 도메인](https://learn.microsoft.com/en-us/entra/identity-platform/howto-configure-publisher-domain)
