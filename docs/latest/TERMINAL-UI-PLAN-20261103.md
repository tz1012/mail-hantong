# 통신풍 터미널 구현 계획

목표: 명령형 `hantong`을 유지하고 `hantong-t`를 고정 화면 통신풍 메일 환경으로 제공한다. 사용자가 2026-11-03 구현을 지시했으므로 과거의 레트로 후속 보류를 이 범위에서 대체한다.

- 화면: 헤더, 계정·폴더 탐색, 목록, 본문, 상태·키 안내. 넓은 창은 목록/본문을 나누고 좁은 창은 읽기 영역을 조정한다.
- 테마: blue(기본 통신풍), green, amber, mono, bbs8(ANSI 8색), bbs16(ANSI 16색). `--theme`와 실행 중 전환을 제공하며 GUI의 light/dark/system과 구분한다. 첫 버전의 선택은 실행 수명 동안 유지한다.
- 입력: 방향키/j/k, Enter, Esc/뒤로, 본문 PageUp/PageDown, 테마 전환, 도움말. 마우스 행 선택·더블클릭 열기·휠 스크롤과 메뉴 클릭을 지원한다.
- 공통 받은편지함: `u`는 준비된 각 계정의 캐시 Inbox를 계정 태그와 함께 하나의 읽기 전용 목록으로 합친다. `v`는 현재 본문 표시 영역을 확장한다. 넓은 화면은 탐색 영역을 제외한 남은 폭의 약 60%를 본문에 배정하고 좁은 화면은 목록과 본문을 쌓는다.
- 표시 별칭: `a`로 계정 별칭을 설정하고 `profiles/terminal-ui.json`에 CAS로 저장한다. 별칭은 표시 전용이며 인증, From, 계정 범위, 공급자 요청과 무관하다. 테마는 아직 실행 중에만 유지한다.
- 시작 안내: 준비 단계에는 짧은 캐릭터 애니메이션을 표시하고, 작업이 끝나면 계정·버전·업데이트 알림을 일반 프롬프트로 이어 준다. 업데이트 알림은 안내이며 자동 설치하지 않는다.
- 구조: 기존 플랫폼 Windows 콘솔 API 뒤에 입력 이벤트와 모드 복원 RAII를 둔다. 외부 의존성을 추가하지 않는다. TUI는 기존 CLI/Core 호출과 단일 메일 확인 경로를 재사용한다.
- 안전: 텍스트의 터미널 제어·bidi를 실행하지 않는다. 읽기용 본문 viewport를 발송 확인으로 사용하지 않는다. 작성·발송·휴지통·AI/비밀 입력 전에는 raw/alternate 모드를 복원하고 기존 같은 터미널 흐름으로 이동한 뒤 복귀한다. 클릭·테마 변경은 발송/삭제를 실행하지 않는다.
- 검증: 순수 렌더링·표시 폭·입력 매핑·클릭 좌표·테마·선택 viewport·제어문자 회귀, 영향 TUI/platform 검사, 빌드/Clippy. 실제 외부 발송·삭제는 새로 실행하지 않는다. 컴퓨터 관찰은 Vercel agent-desktop의 비활성 창 읽기만 사용한다.

완료 기준: 대체 화면이 종료/오류/하위 명령 뒤 복원되고, 기존 계정·폴더·메일 읽기 및 확인 경로가 동작하며, 키보드/마우스와 테마에 검증 근거가 있다. 사람 보안 검토 완료로 기록하지 않는다.
