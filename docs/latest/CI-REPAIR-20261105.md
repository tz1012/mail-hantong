## 원인별 수정

충돌 복구의 AI 보안 코드 검토와 합성 회귀 결과는 다음과 같다. 이는 실제 사람 검토 완료를 뜻하지 않는다.

| 검토 항목 | 보존한 결속·검증 |
| --- | --- |
| 명시적 취소·단일 사용 | owner·OS peer·ticket·kind·request·hash·account selector·expiry·channel·기준 등록을 검사한 뒤 정확한 pending CAS와 ticket 소비를 수행한다. 다른 결속과 재사용을 거부하는 Core 회귀를 유지한다. |
| 만료 순서 | 정상 UTC·정확한 Store snapshot/version으로 expired pending을 먼저 닫고 불일치를 판정한다. Store 회귀는 계정·설정·키·기존 권한 유지를 확인한다. staged는 별도 복구 경로로 유지한다. |
| OAuth와 터미널 출처 | terminal_cli 요청이 기존 OAuth 등록 출처를 덮어쓰지 않는다. OAuth 완료는 OAuth 출처만 허용하고, 터미널 pending은 Confirm 전 자동 활성화하지 않는다. |
| staged 복구 | staged를 취소·만료·교체하지 않고 기존 publish→activate 복구를 재사용한다. 기존 key·pin·epoch·version과 profile 결속을 유지한다. |
| 승인 전 접근 유지 | 새로운 요청·진단·만료·취소는 기존 active 등록·scope를 그대로 둔다. 정확한 계정·도구 preview의 정상 Confirm 이후에만 변경한다. |
| 비밀 비노출 | 진단은 accounts/tools/base_registration/server_binding/decision_channel이라는 닫힌 항목명만 쓴다. 값·주소·요청 ID·키·토큰·메일·하위 예외 문자열은 출력하지 않는 회귀를 유지한다. |

Linux 별도 gate는 Store 만료 1개와 Core scope 관련 7개·출처 2개를 실행한다. 전체 CI와 중복되는 실행이며 고유 시험 수를 더해 부풀리지 않는다. 공개 expired Cancel은 ticket 정리 뒤 CONFLICT가 될 수 있으므로 내부 만료 guard의 APPROVAL_EXPIRED 시험과 구분한다.

| 원인 | 수정과 유지한 검사 |
| --- | --- |
| 지원되는 Unix 경로에 과거 미지원 오류를 기대 | Linux/macOS는 실제 절대 경로·data/secrets/profiles 관계·Debug 비노출을 검사한다. 다른 OS의 미지원 검사는 유지한다. |
| Mac 임시 경로의 `/var`→`/private/var` 별칭 | 유효 fixture만 canonical 경로로 생성한다. 제품 no-follow와 별도 symlink 거부 시험은 유지한다. |
| Darwin Unix 소켓 경로 길이 초과 | fixture 경로를 짧게 만들고 과도한 길이는 거부하며 endpoint를 만들지 않는 음성 회귀를 추가했다. |
| Windows 현재 스키마와 frozen fixture 불일치 | v27 현재 56개 테이블과 이벤트 테이블 초기 공백을 검사한다. frozen v8 복원 fixture는 새 테이블이 비었음을 확인하고 시험 DB에서만 제거한다. 제품 DB·마이그레이션·메일 데이터는 지우지 않는다. |
| 릴리스 버전 루트 자체를 검사하지 않음 | 루트 자체의 타입·symlink·소유자·쓰기 권한을 검사한다. 루트 0777/01777 음성 시험을 유지한다. |
| 중간 bin 경로와 검증 중 파일 교체 | 기존 디렉터리 guard의 no-follow openat를 재사용하고 열린 파일 한 개로 소유자·모드·크기·해시를 검증한다. bin/manifest symlink와 열린 inode 교체 회귀를 추가했다. 비밀 파일 0600 정책은 유지한다. |
| Unix Store 시험의 보호 저장소 미준비 | Linux는 시험 전용 암호화 headless 금고, Mac CI는 전용 Keychain을 준비한다. Mac은 명시 경로·기본 금고·전체 검색 목록의 정확한 일치를 확인한 뒤에만 접근하며 원래 설정을 복원한다. |
| 병렬 fixture의 최초 database-key 생성 경쟁 | Store와 Core는 서로 다른 시험 프로세스이므로 각각 OnceLock 안에서 공개 Store API로 합성 키 준비를 한 번 완료한다. 제품의 ALREADY_EXISTS 거부나 병렬 시험을 제거하지 않는다. |
| Mac의 시간 값만 사용하는 fixture 이름 충돌 | 프로필·릴리스 fixture에 원자 카운터와 배타적 폴더 생성을 추가한다. 시계를 조작하거나 시험을 직렬화하지 않는다. |
| Unix 시작 지원과 어긋난 lifecycle 시험 | 미지원 OS의 거부 시험은 유지하고 Linux/macOS는 빈 relay 입력 거부를 검사한다. Linux는 잘못된 XDG 루트의 정확한 시작 실패 단계를 확인한다. 모든 자식 명령은 5초 제한이며 시간 초과는 실패다. 실제 시작 성공은 별도 네이티브 설치 gate에서 확인한다. |
| Mac의 테스트 실행 파일 간 Keychain 공유 후 정지 | CI 전용 Cargo runner가 실행 파일마다 합성 Keychain을 만든다. 전용 기준 금고·검색 목록 확인, 파일 잠금, 중단·시간 초과 시 자식 정리, 기준 설정 복원·검증 후 삭제를 수행한다. 제품 ACL·키 선택자·승인 정책은 바꾸지 않는다. |
| Mac 실제 PTY 시험의 출력 역압력 | 종료 대기 중에도 PTY 출력을 읽고, 자식 종료와 출력 공백을 함께 확인한다. 원래 8초 제한을 유지하고 512 KiB 출력 회귀를 필수 실행한다. 기존 탐색·크기 변경·q/Ctrl-C 종료·터미널 복원 검사는 유지한다. |
| Mac 복원 뒤 커널의 동적 PENDIN 상태 | 두 Mac 아키텍처에서 독립 OS 전환과 앱 복원 모두 lflag XOR 0x20000000 하나만 달랐다. 매 실행에서 별도 PTY로 얻은 전환의 정확한 방향만 기대값에 반영한다. 속도·전체 CC·제어 플래그 변경과 알려지지 않은 비트는 거부한다. 관찰되지 않은 PENDIN 차이도 거부하는 회귀를 포함한다. 일괄 마스킹은 없다. |
| 외부 stty 문자열을 통한 모드 저장·복원 | 기존 libc로 전체 native termios를 저장·복원하며 모드 적용 실패 때도 복원을 시도한다. 입력 플래그 의미는 유지한다. stty-g가 VMIN/VTIME을 누락한다는 가설은 Apple 소스로 반증됐으며, 이 변경만으로 PENDIN을 없앴다고 주장하지 않는다. |

수정 중 발생한 Mac 전용 Clippy clone 경고는 참조 비교로 해결했고, job env에서 runner 문맥을 사용할 수 없다는 workflow 검증 오류는 runner 단계의 GITHUB_ENV로 옮겼다. 경고 억제·시험 삭제·ignore·continue-on-error·필수 gate 우회는 추가하지 않았다.

## 앞선 결과와 실패 기록

- `28b40a5`, `857e476` Windows 전체 CI는 각각 성공했다. 각 Rust 1,981회 실행은 실패·ignore 0, 문서 29개 통과다. Build 132개 집계에는 빌드 전 TUI 실행 파일이 없어 건너뛴 기존 콘솔 시험 1개가 있다. 이전 진행 기록의 전체 “무시 0” 표현은 Rust 결과에 한정해 정정한다. 해당 콘솔 시험은 이 PC에서 실행 파일을 명시해 별도로 통과했다. 이 결과를 최종 새 소스 전체 통과로 대신 표시하지 않는다.
- `5131622` native Linux는 Store 18/20, Mac package는 Store 17/19에서 ALREADY_EXISTS를 드러냈다. 사전 키 준비로 수정했다.
- `012590f` Linux는 Store를 통과한 후 Core 69/70에서 동일한 최초 키 경쟁을 드러냈다. Core 시험 준비도 공통화했다.
- `eb988a5` Mac ARM은 플랫폼 40/41에서 fixture symlink 생성의 AlreadyExists를 드러냈다. 원자 카운터로 수정했다.
- `695524c` Windows 전체 검사는 성공했고 Linux는 Core 70/70·Store 20/20 이후 오래된 lifecycle 기대값에서 실패했다. Mac은 Core 시험 중 1,800초 제한으로 실패했다. Keychain ACL 대기가 유력한 가설이나 실제 확인 창을 수집한 것은 아니다. 이 실패를 성공으로 계산하지 않는다.
- `e37d7df` Linux 전체 CI는 성공했고 Mac 두 아키텍처의 저장소 전체 검사는 통과했으나 추가 PTY 시험의 종료 대기에서 각각 실패했다. 같은 소스의 Mac 두 패키지·설치 gate는 성공했다. PTY 출력 읽기 수정은 `4211791`에 반영했다.
- 최종 CI runner 모의시험 14개는 Windows와 WSL에서 모두 실행·통과했다. 로컬 문서 29개 통과, Build 146개 실행 중 TUI 실행 파일 탐색으로 건너뛴 기존 1개는 명시 경로로 따로 실행해 통과했다. 최종 네이티브 CI 결과는 아래 표의 기준이다.
- 최종 비교 회귀를 포함한 로컬 Build 153개 실행에서는 151개 통과, 설치 시험 하나의 20초 TimeoutExpired와 다른 하나의 File.Replace 오류가 발생했다. 같은 시간대에 별도의 실제 후보 설치 검증도 진행 중이었다. 이를 원인으로 확정하지 않는다. 후보 검증 종료 후 실패한 정확한 두 시험만 기존 제한으로 다시 실행해 2/2 통과했다. 최초 실패 로그 `target/ci-repair-final-build-tests.log`와 별도 재검사 `target/ci-repair-final-failed-installer-recheck.log`를 보존한다. 실패를 153개 동시 통과로 재표기하지 않는다.
- 로컬 WSL은 UTC 역행이 관찰된 환경이다. 사전 키 준비 후 Store 17/20의 ApprovalExpired 결과는 실패로 보존하며, native Ubuntu 결과로 확인한다. 제품 만료 guard를 완화하지 않는다.
- 먼저 추가한 릴리스 루트 symlink 회귀는 실패했고 이후 `28b40a5`, `857e476`으로 실제 검증 경계를 수정했다. 최초 실패를 통과로 고쳐 기록하지 않는다.
- 수정 전 중복 소스의 자체 CI를 취소한 실행은 취소로 기록하며 통과 수에 넣지 않는다. 사용자의 별도 시험이나 실제 Core는 중지하지 않았다.

## 배포 차단과 필요한 사람 검토

근거는 AGENTS §6·§9, terminal-workflows 첫 문단의 명시적 사람 보안 검토 요구다. [고정 검토 범위·체크리스트·기록 양식](HUMAN-SECURITY-REVIEW-SCOPE-20261105.md)에 기준/대상 고정 커밋과 전체 diff, 취소 단일 사용·만료 순서·출처·staged·승인 전 권한 유지·진단 비노출과 필요한 판단을 정리한다.

같은 UID가 파일 검증과 경로 실행 사이 실행 파일을 바꾸는 기존 TOCTOU 창은 남는다. AI 리뷰는 이를 기존 MEDIUM 위험으로 기록했으며 사람의 명시적 판단은 아직 없다. 추가 조치가 필요하다는 결론이면 배포 전에 구현·재검증해야 한다. CI 통과나 사용자 배포 승인을 이 위험의 자동 수용으로 간주하지 않는다.

Mac의 테스트별 Keychain 분리는 이전 설치 Core가 만든 항목을 새 Core가 읽는 버전 간 호환 시험을 대신하지 않는다. 새 설치·같은 버전 재시작과 구분하며, 이 호환성은 아직 미검증이다.

실제 검토자·UTC·대상 커밋/해시·항목별 결과·발견 사항 조치·잔여 위험 판단·최종 결론 기록이 없는 상태에서는 공식 tag/release/설치 안내를 갱신하지 않는다. 실제 송파 연결 검증도 수행하지 않았고 합성 CI와 구분한다. 기존 계정·금고·메일·인증정보·권한은 삭제하거나 초기화하지 않았으며 실제 권한을 자동 부여하지 않았다.
